## 2. ARCHITECTURE ORIENTATION (for a fresh agent who's never seen this repo)
- **`dm-net/`** (Kotlin) — isolated module wrapping RSProt + Netty. Knows nothing about the game
  model. Talks to the game engine only via functional lambdas injected from `DMS`
  (`FilestoreCacheProvider`, `DmLoginService`, consumer-registry listener bindings).
- **`DMS/`** (Java, the actual game engine — "Kronos") — this is where 99% of the migration work
  lives. Key files:
  - `DMS/src/main/java/io/dm/network/rsprot/RsProt.java` (~1026 lines) — the RSProt integration
    hub: login construction (`doLogin`), the per-tick sync loop (`driveUpdate`/`pushMaskUpdates`),
    and the 15 incoming-packet listener registrations (`start()`).
  - `DMS/src/main/java/io/dm/network/PacketSender.java` (~1056 lines) — every outbound packet
    method. Each has an RSProt-path branch (`queueRsprot(...)` / `queueZonePayload(...)`, returns
    `true` to skip the legacy path) followed by the untouched legacy 184 `OutBuffer` fallback for
    AI bots / anything without a session.

## 11. GLOSSARY (for a fresh agent unfamiliar with this stack)
- **RSProt** — third-party Kotlin library implementing the OSRS network protocol for a given
  revision; this project pins revision 228.
- **RSProx** — a client-side proxy that lets a real, unmodified rev-228 OSRS client connect to a
  custom server (this one) instead of Jagex's servers.
- **Rev / revision** — a specific version of the OSRS client protocol. This project is migrating
  from rev 184 (the original Kronos base) to rev 228.
- **Zone** — an 8x8 tile chunk; ground items/objects/projectiles/graphics/sounds are all addressed
  by which zone they're in, not raw tile coordinates, hence the `x & ~0x7` bug in Section 6a.
- **Mask** — a legacy-184-era bitflag-driven per-tick "this entity changed" structure (animation,
  graphics, hits, etc.). RSProt replaces this whole concept with an `ExtendedInfo` object with
  named setters — "bridging a mask" means reading the legacy structure's current state and calling
  the equivalent RSProt setter once per tick it's dirty.
- **`If3Button`/`IfButtonD`/`IfButtonT`** — RSProt's incoming message types for, respectively, a
  normal interface-component click, a drag action, and an item-on-item action.
- **Access mask (`IfSetEvents`)** — a per-component server→client message that tells the rev-228
  client which click/drag options are even enabled for a given interface component's slot range.
  Without one, the client won't send the corresponding click packet at all — this was the root
  cause of Milestone 4's inventory/equipment click silence (Section 7 history).
