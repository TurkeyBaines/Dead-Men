STAGE 04 — Main (modal) interfaces open
STATUS: NOT STARTED
DEPENDS ON: Stage 00. Stage 01's CACHE_INTERFACE_DUMP.txt extract helps.
Follow the RULES in stages/README.txt.

## GOAL
Interfaces opened as InterfaceType.MAIN (bank, trade, scrolls, equipment-stats, ...) actually
render in the central modal area of the rev-228 client, and their paired inventory-side overlays
(InterfaceType.INVENTORY, e.g. the bank's deposit view) render too.

## SYMPTOM (human-reported 2026-07-08)
"Main interfaces don't seem to open at all." (Chatbox interfaces partially work — smelting fine,
choose-option has a missing background; those are NOT this stage: chatbox routing evidently
works, and the background cosmetic is Stage 11.)

## VERIFIED PRIME SUSPECT — stale 184-era root-child slots
DMS/src/main/java/io/dm/model/inter/InterfaceType.java maps every interface type to a
(parent, child) component of the root frame. Fixed-mode values (parent 548) include:
    MAIN              = 548:21
    INVENTORY(+overlay)= 548:64
    SOCIAL_TAB        = 548:75
    WORLD_MAP         = 548:22
    various overlays  = 548:14..18
These are original 184-era values that were NEVER re-audited for 228. Meanwhile the login frame's
pane table (RsProt.java ~line 98, FIXED_FRAME_PANES, sourced from AlterRSPS's
InterfaceDestination "fixed" column — a genuine 228 reference) shows 548's REAL 228 layout puts
the sidebar tabs at children 80-93, chatbox at 10, minimap at 24 — a completely different layout
from what the 184-era numbers assume. So `Bank.open()` sends a perfectly well-formed IfOpenSub
targeting 548:21 — a child that in the 228 cache is very likely not the modal layer — and the
client renders nothing. This single mapping error would explain EVERY MAIN interface failing
uniformly while server-side logs look flawless (exactly what three rounds of prior debugging
observed — see HANDOFF.txt "Milestone 4 Fix — Live Testing Round 2/3" if you need that history).
Note the server only ever opens the FIXED frame (548) today, so fixing the fixed column is what
matters; correct 161/164 in the same pass if your source provides them, else leave visibly
marked TODO.
