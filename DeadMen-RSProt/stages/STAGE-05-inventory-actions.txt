## PRIME UNTESTED HYPOTHESIS — option-index vs cache mismatch
TabInventory.click decides what to do by comparing the received op against the item's option list
from the SERVER's item definitions — which load from the LEGACY 184 cache (Server.fileStore).
The client builds its right-click menu from the 228 cache. If an item's inventory-option ordering
differs between the two caches (option text moved slots between revisions, e.g. def.equipOption
disagreeing), the server receives a valid op that maps to the wrong/absent server-side action and
silently does nothing — matching the symptom exactly, uniformly, with zero errors. PROTOCOL_DUMP
gives you the received op; dump the server ItemDef's option array for that item id and compare.
