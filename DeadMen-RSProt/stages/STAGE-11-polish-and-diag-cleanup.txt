## ROUND 3 FINDINGS (2026-07-13) — chat heads still broken after the Round 2 child remap
Human report: "NPC Chat Head and Player Chat Head aren't appearing correctly on the Player/Npc
Dialogues." Round 2's 231/217 child remap (head=2/name=4/continue=5/message=6) was real and
correct, but it only fixes WHERE the head/name/continue/message land — it does nothing if the
packets that actually populate those components never reach the client in the first place, and
that turned out to be the deeper bug: **`PacketSender.sendPlayerHead`, `.sendNpcHead`, and
`.animateInterface` were never ported to RSProt at all.** Every other ported send method in this
file has an `if (queueRsprot(...)) return;` branch before falling through to the legacy 184
`OutBuffer` path (grep any of `sendString`/`setHidden`/`sendItem`/`sendAccessMask` for the
pattern) — these three skipped straight to `write(out)`, and `PacketSender.write()`'s own comment
says exactly what happens next: `if (player instanceof AIPlayer || player.getChannel() == null)
return;` — RSProt-bound real players have a null legacy channel by design (Stage-3 bind note at
the top of the file), so the call silently no-ops. NPCDialogue/PlayerDialogue's `open()` was
calling `sendNpcHead`/`sendPlayerHead`/`animateInterface` exactly like Round 2 intended (targeting
child 2, the now-correct head slot) — the child id was right, the packet just never left the
server. `sendString`/`setTextStyle`(->`sendClientScript`)/`sendAccessMask` (name/message/continue
button) were already properly ported, which is why those three DID render — matching the human's
"chat head" (not "everything")-scoped report precisely.
- **Fix**: added the missing RSProt branches, mirroring the existing pattern exactly. RSProt's
  `osrs-228-model` sources jar (`net.rsprot.protocol.game.outgoing.interfaces`) has exact
  equivalents for all three, confirmed by reading the .kt sources directly (not guessed): `IfSetPlayerHead(interfaceId, componentId)`,
  `IfSetNpcHead(interfaceId, componentId, npc)`, `IfSetAnim(interfaceId, componentId, anim)` — all
  three take the same `(parentId, childId[, extra])` shape the legacy methods already use, so no
  parameter remapping was needed, only the missing branch.
- Files touched: `PacketSender.java` (`sendPlayerHead`/`sendNpcHead`/`animateInterface`).
  NPCDialogue.java/PlayerDialogue.java were NOT touched this round — Round 2's child-id remap in
  those files was already correct; this was purely a missing-packet-port bug one layer down.
- Verified: `./gradlew :DMS:compileJava` BUILD SUCCESSFUL. No other call sites of these three
  methods exist in the repo (grepped) — NPCDialogue/PlayerDialogue are the only two, both dialogue
  chat-head paths, so this fix is fully scoped to the reported symptom.
- Options ("not firing at all") is still un-root-caused from Round 2 — the TEMP "SERVER-OUT
  OptionsDialogue.open" diagnostic line is still in place; not touched this round.
